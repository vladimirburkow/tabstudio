# Сервер аккаунтов (Supabase)

Аккаунты, проекты, история версий и исходные записи хранятся в Supabase: Postgres + Auth + Storage + Realtime. Бесплатного тарифа хватает для старта: 500 МБ базы, 1 ГБ файлов, 50 000 активных пользователей в месяц.

## 1. Создать проект
1. supabase.com → **New project**. Регион выберите ближе к пользователям (например, Frankfurt). Сохраните пароль базы.
2. **SQL Editor → New query** → вставьте `migrations/0001_tabstudio.sql` → **Run**. Скрипт можно запускать повторно.
   Он создаёт таблицы `projects`, `project_versions`, `user_meta`, правила доступа (каждый видит только свои строки), функции `save_project` (сохранение с проверкой ревизии), `delete_project`, `delete_account`, закрытое хранилище `audio` и включает мгновенные обновления.
3. **Project Settings → API**: скопируйте **Project URL** и ключ **anon / public** в `config/tabstudio.config.js` → `supabase`. Ключ anon можно класть в клиент: данные защищены правилами RLS. Ключ `service_role` в приложение **не кладите никогда**.

## 2. Настроить вход
**Authentication → Providers → Email**: включено, «Confirm email» — по желанию.

**Authentication → Email Templates.** Приложение входит по 6-значному коду, а не по ссылке: так вход работает одинаково на сайте, в десктопе и в мобильном приложении. В шаблонах **Magic Link** и **Confirm signup** замените текст на:
```html
<h2>Код для входа в Tab Studio</h2>
<p>Ваш код: <b style="font-size:24px">{{ .Token }}</b></p>
<p>Код действует 1 час. Если вы не запрашивали вход, просто удалите письмо.</p>
```

**Authentication → URL Configuration**: Site URL — адрес вашего сайта (например, `https://tabstudio.example.com`).

**Authentication → SMTP Settings** — обязательно для продакшна. Встроенная почта Supabase отправляет всего несколько писем в час и только для теста. Подключите свой SMTP: Resend, Postmark, Mailgun, Яндекс 360 или Unisender.

## 3. Как работает синхронизация
- Всё сначала сохраняется на устройстве (IndexedDB), поэтому приложение работает без сети. Изменения отправляются, когда появляется связь.
- У каждого проекта есть ревизия. Если проект изменили на другом устройстве, приложение не перезапишет чужие правки молча, а спросит: загрузить версию из облака или сохранить свою поверх.
- Если проект менялся на двух устройствах без связи, при синхронизации облачная версия остаётся основной, а правки этого устройства сохраняются отдельным проектом «(копия с этого устройства)». Данные не теряются.
- Исходные записи хранятся в `audio/<id пользователя>/<id проекта>`. Чужие файлы недоступны.
- При первом входе проекты, созданные на устройстве без аккаунта, добавляются в аккаунт.
- Удаление аккаунта в приложении удаляет файлы, проекты, версии и сам аккаунт (требование App Store).

## 4. Проверено
Миграция и сценарии проверены на локальном Postgres 16 с Supabase Auth (GoTrue) и PostgREST: регистрация, вход на втором устройстве, загрузка проекта и записи, изменение на одном устройстве и появление на другом, конфликт ревизий, работа без сети с последующей отправкой, сохранение сессии после перезапуска, удаление аккаунта, изоляция данных разных пользователей.
