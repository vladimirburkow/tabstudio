# Tab Studio: публикация в App Store (и Google Play)

Бесплатное приложение с рекламой Google AdMob и аккаунтами Tab Studio (синхронизация с сайтом и десктопом). Проект на Capacitor 8 собирается из общего кода репозитория (`app/`).

Сборка здесь **не проверялась на Mac и устройстве**: собрать iOS-приложение можно только в Xcode на macOS. Ниже весь путь от архива до публикации.

---

## 0. Что понадобится

| Что | Где | Стоимость |
|---|---|---|
| Mac с macOS и **Xcode 16+** | Mac App Store | бесплатно |
| **Apple Developer Program** | developer.apple.com/programs | $99 в год |
| **Аккаунт AdMob** (Google) | admob.google.com | бесплатно |
| Node.js 20+ | nodejs.org | бесплатно |
| Публичная страница с **политикой конфиденциальности** | ваш сайт, GitHub Pages, Notion | бесплатно |
| Для Android: Android Studio и **Google Play Console** | play.google.com/console | $25 один раз |

## 1. Запуск проекта

```bash
cd tabstudio
npm install                          # общие библиотеки (корень репозитория)
cd platforms/mobile && npm install   # Capacitor и плагины
npm run ios        # собирает www/ из ../../app, синхронизирует плагины и открывает Xcode
# npm run android  # то же для Android Studio
```

Код приложения общий для всех платформ: `app/` в корне репозитория. Настройки: `config/tabstudio.config.js`. После изменений запускайте `npm run sync`.

## 2. Свои идентификаторы

### 2.1. Bundle ID и название
- `capacitor.config.json` → `appId` (сейчас `app.tabstudio.guitar`). Замените на свой обратный домен, например `ru.yourname.tabstudio`, **до** создания приложения в App Store Connect. В Xcode: Target **App** → General → Bundle Identifier.
- Отображаемое имя под иконкой: `CFBundleDisplayName` в `ios/App/App/Info.plist` (сейчас «Tab Studio»).

### 2.2. AdMob
1. AdMob → **Приложения → Добавить приложение** → iOS → «Приложение ещё не опубликовано».
2. Скопируйте **ID приложения** (вида `ca-app-pub-XXXX~YYYY`) в `ios/App/App/Info.plist` → `GADApplicationIdentifier`.
3. Создайте два рекламных блока: **Баннер** (адаптивный) и **Межстраничный**. Их ID (вида `ca-app-pub-XXXX/ZZZZ`) впишите в `config/tabstudio.config.js` (корень репозитория) → `mobileAds.admob.ios`.
4. В `Info.plist` → `SKAdNetworkItems` вставьте **полный** список идентификаторов из руководства Google (developers.google.com/admob/ios/quick-start, раздел «Update your Info.plist»). Сейчас там Google и два партнёра.
5. AdMob → **Конфиденциальность и сообщения**: создайте сообщение **GDPR** (обязательно для ЕС/Великобритании) и сообщение **IDFA** (пояснение перед системным запросом ATT). Приложение показывает форму согласия само через UMP.
6. Пока идёт разработка, оставьте `mobileAds.testAds: true`. Перед отправкой на проверку поставьте `false`. **Не нажимайте на свою настоящую рекламу**: за это AdMob блокирует аккаунт.
7. После публикации привяжите приложение к App Store в AdMob и разместите `app-ads.txt` на сайте разработчика (шаблон в `store/app-ads.txt`).

Android: ID приложения → `android/app/src/main/res/values/strings.xml` (`admob_app_id`), ID блоков → `config/tabstudio.config.js` → `mobileAds.admob.android`.

### 2.3. Политика конфиденциальности
Отредактируйте `store/privacy-policy.html` (имя, email, дата), опубликуйте по публичному адресу и укажите его в `config/tabstudio.config.js` → `privacyUrl` и в App Store Connect.

## 3. Реклама в приложении

| Формат | Где | Правило |
|---|---|---|
| Адаптивный баннер | внизу экрана, над нижней панелью | всегда, если пользователь дал согласие или оно не требуется |
| Межстраничная | после завершения распознавания, перед открытием редактора; после каждого 2-го экспорта | не раньше чем через 60 с после запуска и не чаще раза в 3 мин (`interstitialMinGapSec`) |

Порядок при запуске: форма согласия Google (UMP, если нужна) → запрос Apple ATT → инициализация SDK. Если пользователь запретил отслеживание, показывается неперсонализированная реклама. В **Настройках** приложения есть кнопка «Настройки конфиденциальности рекламы» (её требуют GDPR и правила Google).

Межстраничная реклама никогда не появляется во время записи, воспроизведения или редактирования: только в «естественных паузах», как требуют правила AdMob.

## 4. Проверка на устройстве

1. Xcode → Target **App** → **Signing & Capabilities** → Team: ваша команда разработчика.
2. Подключите iPhone → кнопка ▶.
3. Проверьте:
   - [ ] при первом запуске появляются форма согласия и запрос ATT;
   - [ ] внизу тестовый баннер с надписью «Test Ad», нижняя панель над ним;
   - [ ] запись с микрофона: появляется системный запрос, запись распознаётся;
   - [ ] загрузка MP3 из «Файлов»;
   - [ ] после распознавания показывается тестовая межстраничная реклама, затем открывается редактор;
   - [ ] экспорт открывает системное меню «Поделиться» (сохранить в «Файлы», AirDrop, Guitar Pro);
   - [ ] звук аккордов в утилитах, работа без интернета (всё, кроме рекламы);
   - [ ] iPad: интерфейс с боковой панелью.

Для проверки формы GDPR вне ЕС: `consentDebugEEA: true` и ID тестового устройства в `testDevices` (его выводит лог Xcode).

## 5. App Store Connect

1. **Мои приложения → «+» → Новое приложение**: iOS, название (см. `store/listing.md`), основной язык русский, Bundle ID, SKU (например `tabstudio-001`).
2. **Информация о приложении**: категория «Музыка», дополнительная «Образование». Возрастной рейтинг: в анкете отметьте «Реклама», неограниченный доступ в интернет «Нет». При рейтинге рекламы `ParentalGuidance` выбирайте 9+.
3. **Конфиденциальность приложения**: ссылка на политику и ответы анкеты (таблица ниже).
4. **Цены и доступность**: бесплатно, все страны или выбранные.
5. **Версия 1.0**: скриншоты из `store/screenshots/` (`iphone-*` → 6,9″, 1290×2796; `ipad-*` → 13″, 2064×2752), описание, ключевые слова, URL поддержки, «Что нового».
6. **Сборка**: Xcode → Product → **Archive** → Distribute App → App Store Connect → Upload. Через 10–30 минут сборка появится в разделе TestFlight. Перед загрузкой: `mobileAds.testAds: false`, `MARKETING_VERSION` 1.0, `CURRENT_PROJECT_VERSION` 1 (увеличивайте с каждой загрузкой).
7. **Заметки для проверяющего** (App Review Information):
   > Приложение распознаёт ноты гитары в аудиозаписи прямо на устройстве и строит табулатуру. Для проверки откройте пример «Am–F–C–G и соло» на главном экране или загрузите любой MP3. Утилиты (аккорды, квинтовый круг, гаммы, генератор прогрессий) доступны без записи. Вход в аккаунт необязателен: он нужен только для синхронизации между устройствами. Тестовый аккаунт: review@ваш-домен / пароль. Удаление аккаунта: Аккаунт → Удалить аккаунт. Реклама — Google AdMob; согласие запрашивается через Google UMP и Apple ATT.

   Создайте этот тестовый аккаунт заранее (зарегистрируйтесь в приложении) и впишите его в поля Sign-in Information.
8. Отправьте на проверку. Обычно проверка занимает 1–3 дня.

### Анкета «Конфиденциальность приложения» (App Privacy)

Исходя из данных, которые собирает Google Mobile Ads SDK (сверьте с актуальной страницей Google «Data disclosure for AdMob»):

| Тип данных | Собирается | Связан с пользователем | Отслеживание | Цель |
|---|---|---|---|---|
| Идентификатор устройства (IDFA) | да | нет | **да** | Реклама третьих лиц |
| Данные о рекламе / взаимодействие с продуктом | да | нет | да | Реклама третьих лиц, аналитика |
| Грубое местоположение (по IP) | да | нет | нет | Реклама третьих лиц |
| Данные о сбоях / производительность | да | нет | нет | Аналитика |
| Email (аккаунт) | да, если пользователь вошёл | **да** | нет | Функциональность приложения |
| Аудио и пользовательский контент (записи, проекты) | да, если пользователь вошёл | **да** | нет | Функциональность приложения (синхронизация) |

Ответ на вопрос «Используете ли вы данные для отслеживания?»: **да** (из-за IDFA и рекламы). Поэтому в приложении обязателен запрос ATT, и он уже встроен.

Без входа в аккаунт записи и проекты хранятся только на устройстве.

### Частые причины отказа и как их избежать
- **5.1.1(v)**: если есть регистрация, должно быть удаление аккаунта внутри приложения. Оно есть: Аккаунт → Удалить аккаунт (удаляются аккаунт, проекты, версии и записи).
- **2.1**: проверяющему нужен рабочий тестовый аккаунт, и сервер Supabase должен быть доступен.
- **5.1.1 / 5.1.2**: нет ссылки на политику конфиденциальности или данные в анкете не совпадают с фактическими. Заполните анкету по таблице выше.
- **ATT**: запрос показывается после формы UMP. Не добавляйте свой экран-уговор с кнопкой только «Разрешить».
- **4.2 (минимальная функциональность)**: приложение полноценно работает офлайн, все библиотеки и шрифты лежат внутри сборки. Не убирайте пример проекта: проверяющему нужно, на чём проверить.
- **2.3.7 / метаданные**: на скриншотах не должно быть тестовой рекламы и чужих логотипов. Скриншоты в архиве сделаны без рекламы.
- **Права на музыку**: в описании не обещайте табы известных песен. Пользователь сам подтверждает права на загружаемую запись (флажок в студии).

## 6. Google Play (кратко)

1. `npm run android` → Android Studio → Build → **Generate Signed App Bundle** (.aab), создайте ключ подписи и сохраните его.
2. Play Console → создать приложение → **Безопасность данных**: те же данные, что в таблице выше, плюс «Реклама: да». Заполните декларацию Advertising ID: используется для рекламы.
3. Целевая аудитория 13+ (не «Для детей»), контент-рейтинг по анкете IARC.
4. Для новых личных аккаунтов Google требует закрытое тестирование: 12 тестировщиков в течение 14 дней до выпуска в продакшн.

## 8. Что можно добавить позже
- Встроенную покупку «Убрать рекламу» (StoreKit, например через RevenueCat). Это обычно поднимает доход бесплатных приложений с рекламой.
